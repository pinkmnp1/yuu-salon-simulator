# ゆうサロンスキャナー（買取スキャン＆MNP利益ツール）

買取店10社の公開価格を毎時集めて、**店頭の値札を入れるだけで「買い / スルー」が分かる**アプリです。
2026-11-19 夜に「初心者向け・神アプリ」版へ更新しました。

公開URL：https://pinkmnp1.github.io/yuu-salon-simulator/

## 5つのタブ（せどり・買取）

| タブ | できること |
|---|---|
| 📷 スキャン | JAN・型番で買取相場を引く → 店頭価格と**ポイント還元率（%）**を入れると「◎買い / △微妙 / ✕スルー」を大きく判定。16社の買取額・前日比・還元率もその場で表示 |
| 🏬 高還元家電 | **普通に買える家電（炊飯器・レンジ・ドライヤー・掃除機・テレビ・カメラ・オーディオ）**のうち、買取額÷実売価格（＝還元率）が高い順に表示。ジャンル絞り込み、ポイント10/20/30%時の実質利益、実売価格の取得元（量販店名）も表示。**既定は大手家電量販店のみ**（＋ネット通販も含めるトグルあり） |
| 📈 急騰・相場 | 前日比の集計（値上がり/値下がり/比較件数）と**急騰TOP20**、値崩れ注意リスト。商品をタップで詳細へ |
| 💰 予算逆算 | 枠の金額を入れると**利益が最大になる買い合わせ**を自動で計算（重複上限つきナップサック）。💎ポイント消化／💰実質負担のモード切替、レジ支払・獲得ポイント・実質負担・買取・残りの内訳、✕除外して入替、端数候補の追加、商品タップでスキャン詳細へ |
| 💎 ポイント | ポイント換金・売却先比較（従来機能） |

MNP利益・回線管理・審査/BL・光回線・実績・申告メモは、上部の「📱 MNP・回線」にまとまっています。

### 実売価格の取得先（2026-11-19 追加）
- 実売は価格.comの**実店舗のある大手家電量販店**（ヨドバシ・ビックカメラ・楽天ビック・ヤマダ・コジマ・ソフマップ・ノジマ・ケーズデンキ・エディオン・Joshin・ベスト電器・イオン・キタムラ）の最安を採用。
- **Amazonは店頭値引きの対象外**なので、大手量販店の判定からは外しています（「＋ネット通販も含める」を押したときだけ🌐マーク付きで表示）。
- カデココ・サンサンマーケット・XPRICE・ディーライズ・PCあきんど等の**通販専業店は既定では出しません**（「＋ネット通販も含める」を押すと表示・🌐マーク付き）。

### 高還元家電の数字の意味
- **還元率** = 買取屋の最高額 ÷ 実売価格（価格.comの量販店最安）。80%なら1万円で買って8,000円で売れる商品。
- **実質利益（ポイント20%）** = 買取額 − 実売価格×0.8。ポイント分だけ安く買ったのと同じ考え方。
- **除外**：ゲーム機・トレカ・端末、オンライン抽選/限定/多言語版などの「店頭に並ばない品」、
  買取額が実売以上のプレ値品（還元率100%超）、中古・ジャンクは出しません。

## データの作り方（毎時23分・VPS `/opt/scanner`）

```
cron_hourly.sh
 ├─ enrich.py --limit 400      … 価格.com（実売）と買取wiki（JAN検索）を補充（キャッシュ24〜72h）
 ├─ update_prices.py           … 買取10社を取得 → scan_db.json に quotes / 実売 / 前日比 を書き込み
 │    └ history/YYYY-MM-DD.json … 日次スナップショット（21日分）
 └─ publish.sh                 … GitHub（pinkmnp1/yuu-salon-simulator）へ push → Pages 反映
```

- **前日比・先週比**は「昨日も今日も価格がある同じ店」どうしで比較（途中から増えた店の分は除外）。
  そのため、店を増やした日の見かけの値上がりは出ません。
- 初回は 2026-11-18 の実測DBを基準として `history/2026-11-18.json` に投入済み。
  急騰ランキングは翌日以降、自動で毎日更新されます。
- 実売価格は `retail_cache.json`、買取wikiは `wiki_cache.json` にキャッシュ（リポジトリには積まない）。

## 自動取得している店（10社）

買取商店・家電市場・買取ルデヤ・森森買取・携帯空間・トゥインクル・ドラゴンモバイル・ジェーシカ
＋ **買取ホムラ（公開JSON API・996件）** ＋ **買取wiki（JAN検索）**。
取れなかった店と理由は `SHOPS.md` に全部書いてあります。

## 手元で試す

```bash
python3 update_prices.py --dry-run                     # 取得して差分を見るだけ
python3 update_prices.py --source homura --limit 2     # 買取ホムラだけ2ページ
python3 update_prices.py --source wiki                 # 買取wikiキャッシュを合流
python3 enrich.py --limit 20                           # 実売価格と買取wikiを20件だけ補充
```

Python 3.9 以降の標準ライブラリだけで動きます（GitHub Actions 用）。
VPS では `/opt/pwenv/bin/python`（Playwright入り）を使っています。

## つまずいた時

- アプリの上に「8,xxx件・2026-11-19 22:00 JST時点…」と出ていれば最新です。
- 高還元家電が空 → 実売価格の収集途中です。`/var/log/enrich.log` を確認。
- 急騰が「まだ前日データがありません」→ `history/` に前日分があるか確認。
- GitHub Actions は毎時の配信が不安定なため、価格更新の本体は VPS の cron（毎時23分）。
